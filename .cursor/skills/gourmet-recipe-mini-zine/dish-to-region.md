# 仅知菜名 → 补全地域与四维

用户只给菜名时，Agent **必须先补全地域单元并给出填好的四维表**，默认请用户确认后再生成图（用户说「直接做」可跳过确认）。

## 推断顺序

1. **项目文档** — `docs/china/*.md`、`docs/world/*.md` 中是否已有该菜及产地列  
2. **菜名自带地名** — 文昌鸡→文昌/海南；东坡肉→杭州/江南；兰州拉面→兰州/甘肃  
3. **常识推断** — 知名菜系与发源地（见下表）  
4. **仍不确定** — 列出 2–3 个候选地域 + 简要理由，用 AskQuestion 或文字请用户选一  

**不要**在不明时默认套「海南椰林深绿宋服」。

```markdown
确认后生成四套 mini-zine → `asserts/mini-zine/{slug}_*.png`
```

## 菜名无地名时的粒度选择

| 情况 | 地域单元建议 |
|------|----------------|
| 省际名菜、多地流行 | 省名（如四川火锅 → 川渝） |
| 有明确县级发源地 | 市县名（如和乐蟹 → 万宁和乐或三亚推广） |
| 城市街头小吃 | 城市（如海南粉 → 海口） |
| 国际菜 | 国家或城市（如寿司 → 日本；披萨 → 意大利/那不勒斯） |
| 完全_generic（如蛋炒饭） | 必须问用户目标地域或叙事场景 |

## 四维快速填充规则

补全地域单元后，打开 [regional-dimensions.md](regional-dimensions.md) 对应行；若无行则仿最近邻地域新建一行（如「陵水」仿「三亚」减度假、加县城市井）。

- **故事底栏**：`{地域标签}风味 | {一句与菜相关的 slogan}`  
- **做法底栏**：`{味型关键词} | {地域标签}经典`  
- **Q版**：先定 **时代代号**（[dynasty-chibi.md](dynasty-chibi.md)，古代→2026；不确定则候选池 `hash(slug)` 随机），再配地域道具  

## 与用户对话示例

**用户**：按 mini-zine 做和乐蟹  
**Agent**：推断地域为万宁和乐/三亚海味推广；给出四维表 → 确认后生成 `hele_xie` 或 `sanya_hele_xie` 四套。

**用户**：做东坡肉  
**Agent**：推断江南杭州；背景西湖荷景；角标江南风味；Q版宋服 → 确认后生成。

**用户**：做麻辣烫  
**Agent**：多地版本 → 列出四川/东北/重庆等候选，请用户选定地域单元后再填四维。
